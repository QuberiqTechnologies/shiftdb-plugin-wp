ShiftDB – Features List
Author: Quberiq Technologies
Contact: contact@quberiqtechnologies.com
Version: 1.0.1

============================================================
CURRENT FEATURES INCLUDED IN VERSION 1.0.1
============================================================

SECURE SEARCH & REPLACE
- Dry-run mode before database changes.
- Search and replace across selected WordPress database tables.
- Case-sensitive search option.
- Serialized PHP data awareness.
- WordPress post GUID protection enabled by default.
- Per-table affected row and replacement counts.
- Preview summary before live replacement.
- Server-side table validation so requests cannot target arbitrary tables.
- Administrator capability checks.
- WordPress nonce protection on mutating requests.
- Structured AJAX error handling.

RECOVERY & UNDO FOUNDATION
- Automatic row-level recovery snapshot before a live search-and-replace operation.
- Recovery point browser.
- One-click restore of affected rows from a recovery point.
- Recovery point deletion.
- Protected recovery storage under WordPress uploads.
- index.php, .htaccess and web.config protection files for recovery storage.
- Conservative uninstall behavior that preserves recovery data.

DATABASE MANAGEMENT
- Database overview with table count and total size.
- Per-table row count.
- Storage engine information.
- Per-table data/index size.
- Table overhead display.
- Selective table optimization.
- Selective SQL export.
- Read-only autoload analyzer showing the largest autoloaded options.

DATABASE CLEANUP
- Post revision cleanup.
- Spam comment cleanup.
- Trashed comment cleanup.
- Expired transient cleanup.
- Cleanup operations use WordPress core deletion APIs where practical.

OPERATION HISTORY
- Local ShiftDB audit log.
- Logs dry runs, live replacements, restores, snapshot deletion, cleanup, table optimization and exports.
- User ID, status, timestamp and non-sensitive operation metadata.
- Search and replacement values are not written to the operation history.

USER EXPERIENCE
- Modern WordPress admin interface.
- Responsive desktop/tablet/mobile layout.
- Five primary management areas: Search & Replace, Database, Cleanup, Recovery and History.
- Select-all controls for database tables.
- Clear operation success and error states.
- Confirmation before destructive operations.
- Prevents live replacement until a successful matching dry run has completed in the current screen state.

SECURITY PRINCIPLES
- No file manager functionality.
- No PHP or JavaScript editor.
- No arbitrary executable-code insertion or execution.
- No executable code downloaded from external sources.
- No feature gating or trialware in the WordPress.org build.
- Capability checks for all privileged actions.
- Nonce verification for AJAX and export actions.
- Input sanitization and database table allow-list validation.
- Output escaping in the WordPress admin UI.
- Recovery files are generated with random snapshot identifiers.

POTENTIAL COMMERCIAL ECOSYSTEM FEATURES
These should only be introduced in a WordPress.org-compliant way. Functionality included in the free directory plugin must remain fully usable and must not be artificially locked.

- Separate optional add-on for remote/cloud backup destinations.
- Separate optional add-on for agency multisite reporting.
- External SaaS-based centralized monitoring, only with clear consent and privacy disclosure.
- Separate enterprise reporting/integration add-ons.

============================================================
IMPORTANT PRODUCT DIRECTION
============================================================

ShiftDB should remain a database maintenance, migration-safety and diagnostics product. Avoid adding arbitrary code execution, PHP/JavaScript editors, file-manager functionality or external executable-code downloads, because these conflict with current WordPress.org submission requirements.

Before public submission, the product name should be re-checked for trademark/project-name conflicts, the complete plugin should be tested with WordPress Plugin Check, and all legitimate findings should be resolved.
